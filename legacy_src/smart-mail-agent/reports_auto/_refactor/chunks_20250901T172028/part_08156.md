     2
     3	Dependencies are stored in a map from *triggers* to *sets of affected locations*.
     4
     5	A trigger is a string that represents a program property that has changed, such
     6	as the signature of a specific function. Triggers are written as '<...>' (angle
     7	brackets). When a program property changes, we determine the relevant trigger(s)
     8	and all affected locations. The latter are stale and will have to be reprocessed.
     9
    10	An affected location is a string than can refer to a *target* (a non-nested
    11	function or method, or a module top level), a class, or a trigger (for
    12	recursively triggering other triggers).
    13
    14	Here's an example representation of a simple dependency map (in format
    15	"<trigger> -> locations"):
    16
    17	  <m.A.g> -> m.f
    18	  <m.A> -> <m.f>, m.A, m.f
    19
    20	Assuming 'A' is a class, this means that
    21
    22	1) if a property of 'm.A.g', such as the signature, is changed, we need
    23	   to process target (function) 'm.f'
    24
    25	2) if the MRO or other significant property of class 'm.A' changes, we
    26	   need to process target 'm.f', the entire class 'm.A', and locations
    27	   triggered by trigger '<m.f>' (this explanation is a bit simplified;
    28	   see below for more details).
    29
    30	The triggers to fire are determined using mypy.server.astdiff.

    33

    35	  visible property of 'x' changes, this gets fired. For changes within

    37	  change in MRO). Smaller changes, such as changes to some attributes, don't
    38	  trigger the entire class.

    41	  base class (relevant if it's accessed through a value of type 'Cls'
